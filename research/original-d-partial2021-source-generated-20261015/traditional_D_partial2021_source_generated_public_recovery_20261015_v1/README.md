## Cold verification

Use Python with NumPy 2.3.5 and Polars 1.44.2. No environment, package wheels,
credentials or bytecode is bundled. Extract into a fresh directory and run:

python -B verify_recovery.py --cpu ASSIGNED_IDLE_CPU --output NEW_RECEIPT.json

Before importing numerical code the verifier confines its process to that CPU,
sets all six numerical thread variables to one, and disables bytecode. It runs
the copied generated tests, mock/synthetic tests and eight exact independent
generated tests. Four two-CPU runner tests are skipped in a one-CPU run. The
original independent generated script's historical CPU4 request is explicitly
remapped at load time to the assigned CPU only; its file bytes stay unchanged.

The six additional packet tests check exact dependencies, nine cells, calendar,
terminal60, fail-closed missing actual inputs, invalid template rejection and
nine metadata-only negative mutations. For metadata validation only, its missing
artifact callback is explicitly replaced by the three copied JSON metadata
bodies. This seam cannot validate omitted target/source bits or create a scope.
Actual source callbacks, provider iterations and historical constructors are
blocked during those negative mutations. Temporary generated account, process,
claim and saved-result tests remain synthetic and distinct from live claims.

COLD_TEST_RECEIPT.json and COLD_TEST.log report the observed cold run, including
passed/skipped counts and resource observations. Host quota enforcement and
full-history resource success remain unverified. Archived two-worker generated
profile evidence is retained but does not certify an actual historical run.
