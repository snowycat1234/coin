# P07 离线集成验收合同

2026-09-30登记，先验收代码与故障，不等待真实180天。
实际测试环境下单另记；此合同不表示已经在交易所完成验收。

## 需要贯通的接口

策略/目标订单 → 独立风险检查 → 唯一客户端订单号 → 持久发单意图 →
测试环境接口 → 状态查询/成交查询 → 资金/资产总额对账 → 持久恢复。

仅固定币安现货测试环境地址，默认网络关闭。
离线使用虚构密钥和HTTP响应，不读取用户密钥或发送交易所订单。
真实订单的过滤器、实际账户费率、可用与锁定余额不能使用历史回测假定值替代。

## 必须产生证据的场景

| 场景 | 通过判据 |
|---|---|
| 正常提交和成交 | 意图先持久化；订单、成交、现金、币数可关联 |
| 发单超时/5xx/-1007 | 状态未知且冻结；不重新POST同一目标 |
| 初次查询不存在 | 不把异步查询的暂时缺证解释为确定拒绝；继续冻结 |
| 查到已成交 | 通过订单号取成交与佣金，对账后方能解除未知状态 |
| 同一目标再次提交 | 返回已有意图/状态，不产生第二个网络订单 |
| 重复成交查询 | 同一交易编号只扣一次资金和佣金 |
| 部分成交后撤单 | 已成交部分保留；撤单过程的新增成交必须查询计入 |
| 撤单超时 | 订单仍可能活跃，不能释放资金后创建替代单 |
| 数量/价格/金额过滤器 | 发单前拒绝非法规格，不向下误舍入而突破金额边界 |
| 费用或锁定余额 | 资产按free+locked核对；佣金按币种计入；不重复预占 |
| 对账不一致/测试环境重置 | 冻结并保留差异；不静默把本地余额改成远端余额 |
| 重启及未知状态恢复 | 恢复相同客户端订单号，先查询，不能重发未确定订单 |
| 限频/封禁 | 遵守Retry-After；冷却期间请求不外发 |
| 单写者/事务故障/审计 | 无重复写者；事务失败不出现一半资金更新；审计链可核验 |

官方依据：[现货测试环境REST](https://developers.binance.com/en/docs/products/spot/testnet/rest-api)。
5xx和超时存在已经执行的可能，REST数据源可能异步，查询缺证不能授权重复下单。

## 输出与状态

1. 每个模块先保存独立测试结果和支持边界。
2. HTTP签名构造与持久订单引擎串联跑一条“超时→查询成交→对账→重启”路径。
3. 报告标记`offline_engineering`，网络订单数为0，真实测试环境天数为0。
4. 代码完成、离线通过、真实接入通过、真实30天通过分别记录。

未知状态未解除、对账差异未解决、没有阶段证据或缺少凭证时，真实入口拒绝启用。
实际测试环境凭证只在接入阶段配置；真钱授权仍是独立最后一步。

所有程序通过D盘hpc_linux的共享5GB内存约束运行，SQLite放在D盘WSL原生文件系统。
