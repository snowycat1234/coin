# 本机实时任务窗口 · 已验收

用户2026-10-02明确要求长训练、测试及磁盘扫描时能实时查看进度。本模块是此前
“不增加dashboard”的明确窄例外，只显示运行任务，不扩交易或研究功能。

## 查看

地址：<http://localhost:8765/>。窗口已在Codex浏览器打开；每2秒自动刷新，可手动刷新。
内容：实际完成配置/日文件数、当前阶段、耗时、最后活动、共享RAM/峰值/上限、
swap及最近一次已完成的完整项目＋整个D盘VHD磁盘扫描。

当前已经运行的十配置诊断保持原源和预算，没有注入监测或重新训练；其TLOB轮次
尚未持久化，窗口诚实显示未知，只显示实际6/10配置、当前模型耗时及检查点更新时间。
服务读取小凭证、进程状态和cgroup计数；不读模型权重，不在每次刷新时扫描项目树。

## 后续所有长任务入口

在 `hpc_linux` / `/mnt/d/codex/coin` 中：

```sh
bash scripts/with_task_progress.sh --title '任务名称' -- 原命令及参数
```

该入口内部仍使用原bounded.sh和共享5GB/swap0约束。可用于模型运行、参数验收测试、
GitHub同步等命令；标准输出保持原样，结束凭证记录实际退出码及信号退出。
Python只在显式启用时读取自身主线程现有循环计数，不更改随机种子、模型、数据或算法：

- 序列训练：当前轮次已完成批次/总批次，原上限和原提前停止规则保持。
- TS2Vec：官方对象实际已完成迭代/预定迭代；样本编码显示已完成样本。
- 共同表格样本准备：已完成样本/总样本。
- pytest：当前测试之前的已完成数量/收集总数。
- 原磁盘守卫：实际已计入字节、待扫描目录。总文件数未知，显示不定进度。
- 没有可读取循环计数的阶段：显示阶段、耗时和“总量未知”，不推算百分比或ETA。

完整磁盘容量显式测量使用同一入口执行 `scripts/task_progress_disk_check.py`；
它调用原 `quant.disk.check()`，守卫源码不改，只保存扫描完成后的ledger和真实时刻。

若窗口服务不在运行，先经bounded.sh运行 `scripts/task_progress_window.py` 并打开地址。
关浏览器不会停止训练。WSL重启后需重新启动服务；本模块没有新增定时观察器。
运行凭证和计数位于D盘VHD内的 `/home/xflops/coin-state/task-progress/`，不进入Git。
服务仅绑定127.0.0.1，没有任务启动、停止、参数修改或文件访问接口；页面无外部资源。
