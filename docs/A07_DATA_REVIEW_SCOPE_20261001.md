# A07 质量报告与阶段门槛解释修缮

2026-10-01。对照用户纠偏方案8.4/8.5、冻结质量实现和专项测试复核。

## 保持的既有规则

冻结`coverage()`的14/30天数据审查条件已经与strict clean日分开：连续共同完整导出
UTC日段中，BTC/ETH实际同秒可用交集至少1,209,600/2,592,000秒。坏秒、断开不确定秒
全部扣除；出现损失时需要更多日历时间。现有坏日仍可审查用例保留。
不修改阈值、交集分母、连续性或原报告，也不把数据审查资格当成训练或alpha授权。

源码确定存在23h50m连接轮转政策，但所有finally断开使用
`reason="rotation_or_disconnect"`，未给每次实际断开独立的计划轮转证明。
因此旧账本中的模糊断开只能记`UNCLASSIFIED_DISCONNECT`。时间相近或源码政策可以
作为背景，不能单凭它标记某次实际断开正常，更不能恢复坏秒或健康credit。

## 新协议范围

新增`A07_DATA_EVIDENCE_REVIEW_v2`协议与只读消费者，分别展示：

1. 完整共同UTC日的报告是否完成，并公布全部排除量/原因。
2. 原定义的strict clean日与原质量状态，保持原值。
3. 实际闭合24h资源、raw年龄/4GB、完整日特征上界×180×1.3/8GB、native未来增长与
   整个项目＋整个VHD的独立证据是否齐备，留给主代理复核。
4. 原14/30天数据审查阶段。相隔片段、两币最小值、无效空桶不能补足交集。

第56项的24h容量/质量报告可以明确包含坏秒与排除，并不要求把有损失的日子写成
零异常质量通过。资源证据缺失/未知/超界时仍待验收；旧版QA_ONLY或
INSUFFICIENT_EVIDENCE不重写。新增消费者不会自动授予actual_24h容量/质量、
训练、alpha或健康时间。

当前仍无完整共同UTC日，真实输入只能提供QA与待验收结果。新协议/消费者还在
实现与验收，不能视为完成或改变57/64。无需替换当前采集版本来实现这项解释修缮。
