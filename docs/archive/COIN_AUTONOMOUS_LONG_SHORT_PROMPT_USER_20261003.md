“支持做空”至少表示：负目标未被上游/下游静默裁剪，能实际生成开空、加空、减空、平空与必要反手，形成正确的持仓、现金流和净值。仅添加 can_short、枚举、接口或单元测试不算完成。

允许复用成熟引擎，或从已有 carry 会计提取最小可复用实现；自己比较迁移成本和正确性，选择较短路径。不要为补做空重建交易平台，也不要复制整套 V1/V2/V3 文件绕开正常版本管理。保护旧证据不等于禁止修改当前代码：使用 Git/冻结快照保留历史，行为变更产生新结果并运行相关回归。

本次默认不提高已授权的名义敞口数值上限，采用明确的单向持仓和逐仓研究模型。若当前仍为单币30%、组合60%，新研究将其定义为绝对名义敞口约束；现货、合约及各策略腿的资金和敞口都须累计，不得各自重复占用同一预算。分别约束/报告净敞口、总绝对敞口、保证金占用和实际波动。保留更严格的既有约束。

## 三、必须正确的金融语义；实现路径由你决定

### 仓位与订单

统一有符号仓位语义，保留产品、交易所、结算资产、数量单位及合约乘数。相同 BTCUSDT 字符串不能把现货和永续合并成同一个工具。

风险计算使用 sum(abs(notional))/NAV 控制 gross，使用有符号暴露计算 net；波动估计使用正确的有符号权重和协方差，不能因净敞口为零而跳过风险控制。检查 np.clip、max(0,...)、weights.sum()>0、仅正仓止损、卖出不超过现货库存等 long-only 假设，并按产品修复，不做盲目全局替换。

反手必须在会计上拆分平旧仓与开新仓；订单可否合并由实际执行语义决定。部分成交、拒单、撤单、延迟和数量精度必须反映到剩余仓位，不能瞬间变号。reduce-only 不得穿过零变为新仓。目标从 +0.3 到 -0.3 的交易量不能只按0.3计费。风控减仓优先于 alpha 最短持有要求。

### 现金、盈亏与资本

在线性合约数量已换算为带符号 base 数量 q 后，固定头寸价格损益应与 q*(exit_price-entry_price) 一致；正q为多，负q为空。增减仓须正确更新成本基础、已实现/未实现盈亏。

开空的合约名义卖款不是可再次投资的现金。保证金划转不是损益；平仓释放抵押物不是新增利润。钱包、已实现盈亏、未实现盈亏和占用/可用保证金不得漏算或重复加算。NAV包含全部投入与预留资金，不得用较小保证金作分母包装高APR。

交易成交价、mark price、index price分工明确。标记价/指数价不能未经说明直接当可成交价。买入/回补与卖出/开空的点差滑点方向正确；已反映在成交价的成本只计一次。若只具备代理价格，结果标记条件筛选，不宣称可执行优势。

### 资金费、费用与保证金

资金费按实际产品的结算事件、rate单位、持仓归属和当时标记价计入。有符号q的标准现金流核对应为 -q*mark*rate：正资金费下多头支付、空头收入；负资金费反向。核对输入rate是比例、百分数还是bp，不根据盈亏猜单位。未来最终结算费率不能提前进入交易信号；结算边界不确定时保留敏感性说明。

按对应产品查询官方规则并绑定费率假设，不能把现货账本换成合约手续费冒充合约回测。沿用现有 Bybit 意向时，Binance 数据只能称 Binance 来源研究或明确的跨场所代理；Bybit原生输入不可得，不要改名假装取得，也不要绕过访问限制。

计入交易费、资金费、保证金和持仓压力。保证金不足、极端上涨挤压空头、跳空、持仓数据缺口均须有明确处理。已具备数据时实现适用的维持保证金/清算规则；缺失时不编造“安全未清算”，只允许明确假设下的有限筛选，并把未建模压力情景标为不可评价。不得把资金费未知直接补零作为主结果，或在账户破产后继续假交易。可以使用事前登记的假设敏感性，但不授真实资格。

### 有针对性的验证

先用小型手算和独立参考账本验证，再跑市场历史，至少覆盖：
- 无成本下在100开空1单位、90平仓毛赚10、110平仓毛亏10；多头符号相反。
- 资金费正负、开仓前/平仓后不归属、事件恰逢成交的固定顺序。
- 部分平仓、反手、重复事件、reduce-only超量，以及费用和抵押物只记一次。
- gross绝对值约束、净敞口接近零但gross很大、价格漂移后的超限与实际执行延迟。
- 保证金不足/跳空/缺失、策略风控减仓，以及未来数据变化不影响过去决策。
- 同一成交序列的经济恒等式、相关Spot兼容性和完整活动入口回归。

不要求先完成所有生产异常场景才做筛选；但直接影响本次损益与风险的错误必须修。不能用旧版本绿测替代新入口，也不要反复重跑无关验收。

## 四、第一轮优先回答：做空到底增加了什么

优先选择已固定、确实有双向语义的公开趋势策略或现有预测策略，不靠新参数搜索制造首个结果。恢复的是完整入场/退出含义，不是把所有非多头状态都改为空头；对原策略的必要风险适配必须明确命名。SMA等教学策略可用于能力验证，但不是整个开源市场的强基准。

在同一永续价格、资金费、费用、初始资本、风险规则和日期下，比较同一个固定双向信号的：
LONG_ONLY / SHORT_ONLY / LONG_SHORT / CASH。

这组是首轮隔离做空贡献的默认对照，不是以后每版都必须重复的模板。保留旧Spot策略作另一个产品参照，但不能把“现货多头→低费率合约多空”的全部差异归因为做空。

优先用现有合法完整共同窗口；已查看历史如实标记开发筛选，不改名unseen，不为凑长度填零资金费，不只挑跌市。既有547/122/90日结果如仍适用，保持各自账户边界，不拼接成长期实盘。新数据范围不得触及封存集。

报告实际评价天数、总资本、gross/net损益、多空分别贡献、资金费、交易成本、换手、平均/峰值gross与net、实际波动、回撤和收益集中度。说明更好是来自空头净贡献、降低暴露，还是其他产品/资金/成本变化。不同策略实际风险不等时，不用相同caps冒称风险匹配；需要时采用事前确定且只用过去信息的风险调节。

方向消融回答实现和机制问题，不足以证明长期alpha；后续在未用于选择的数据或真正前向记录验证。没有做空机会或证据不足就如实报告。若空头拖累，可以采用多头+择时空仓、选择性做空或对冲；不能因用户要求支持做空而强行把空头设为主力。

## 五、以后每版自己决定，不等待用户继续发工单

每个有意义版本完成后，用几句话给出决策摘要：当前主力研究方案是什么；与合适公开策略/强基准差在哪里；主要瓶颈属于信号、方向覆盖、成本、风险、执行、数据还是证据不足；下一项什么工作最可能以合理成本改善投资质量或排除错误方向。

比较少量真正不同的可行路径，通常选择一个主任务，余力允许再做低成本探测。自己确定预算、对照、主要指标和停止条件，运行前简记即可，不要求新建复杂协议平台或虚构精确的信息增益分数。

你可以自主选择复用策略、调整未来实验的持仓周期/特征/模型、优化退出/成本/风险、研究选择性多空、补必要数据、组合或暂停某条路线；不必永久坚持微观结构、均线、carry或某个模型。不为“自主”每版重换技术栈，不因一个窗口失败永久封禁整个方向。

普通研发在现有授权内直接实施。达到停止条件后选择采用、保留、简化、暂停或换路；预算允许继续推进，不允许无限搜参。运行窗口结束就留下可执行交接点，不声称已经在后台持续工作。

保留一个稳定研究主力和少量挑战者，按预先确定的选择方法竞争。无增量就保留主力；投资主力/真钱候选可以仍为NONE。允许复用方案成为研究主力，不把复用包装成原创，不把每个测试期事后最佳策略拼成可实时交易的组合。

工程验收、收益筛选、候选资格和真钱部署分开。支持多空是能力，采用哪一边是研究结论；研究方案可运行不代表已获盈利资格。负结果、排除错误假设、降低尾部风险均可构成进步，不要求每版收益上涨，也不能一直用更多文档替代经济结果。

## 六、不可为了提速绕过的边界

决策/训练/资产选择只能使用当时可得信息；保持时间切分、标签成熟和适当OOF。保留全部影响选择的试验、旧亏损和数据缺口，不能事后改成本、挑日期、反转方向或更换成功标准来宣称同一实验通过。开发阶段可以迭代，但反复查看的历史不再提供独立确认。

遵守当前已授权的磁盘、RAM、CPU和数据限制，保护正在运行的任务。真实资金、账户密钥、测试网/主网发单、提高杠杆或风险额度、启封holdout、购买数据与规避服务限制均不在本次自主权限内。不要为了低成本展示永久跳过执行与后续验证。

高级统计按证据阶段采用：先有正确账本和配对对照，再选择合适的依赖稳健区间与多重选择控制。不用几天结果宣称稳定APR，不把重抽样次数当市场历史长度。最终长期优势必须由充分独立证据支持。

每版只维护必要的现有状态页、简短决策日志、实验记录和结果，交付可复现命令及实际工件。最终回答先说：
“本版补齐了什么？是否出现真实空头成交？它对净收益/风险的实际贡献是什么？当前采用什么？下一步为什么做这件事？”

立即从当前HEAD实施，不只回复计划。第一轮成功标准是：做空成为可验证的真实研究能力，完成可信的方向对照，或交付已实施的最小修复与精确阻塞证据；不是制造正收益。
